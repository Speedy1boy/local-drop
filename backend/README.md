# Local Drop | Backend

REST API и WebSocket сервер приложения на базе NestJS. Отвечает за работу с файловой системой, бизнес-логику, авторизацию и управление базой данных.

## Архитектура
- **REST API:** Обработка CRUD операций, загрузки файлов (Multer) и выдачи статики.
- **WebSockets (Socket.io):** Гейтвеи для оповещения клиентов об изменениях в файловой системе, буфере обмена и заметках в реальном времени.
- **База данных:** PostgreSQL для хранения метаданных файлов, иерархии папок, сессий, логов безопасности и настроек. Физические файлы сохраняются на диск в папку `uploads/`.
- **ORM:** Prisma для типизированного взаимодействия с БД.
- **Безопасность:** Авторизация по PIN-коду (JWT), защита от брутфорса, throttling запросов, блокировка подозрительных IP.

## Модули
| Модуль | Описание |
|---|---|
| `auth` | Авторизация (PIN/пароль), JWT-сессии, админ-панель, IP-блокировки |
| `files` | Загрузка, скачивание, удаление файлов. Управление папками |
| `clipboard` | Общий буфер обмена с real-time синхронизацией |
| `notes` | Заметки с тегами и real-time синхронизацией |
| `prisma` | Подключение к базе данных |

## Подготовка базы данных

### Автоматически (из корня проекта):
```bash
npm run db:up        # Поднять PostgreSQL в Docker
npm run db:migrate   # Применить миграции
```

### Вручную:
```bash
npx prisma migrate dev --schema=./prisma/schema.prisma
```

### Синхронизация файлов:
Если база данных была пересоздана, а файлы в папке `uploads/` остались на диске, выполните синхронизацию для восстановления записей в БД:
```bash
npm run db:sync      # Из корня проекта
```

## Локальный запуск

Запуск осуществляется через скрипт в корне монорепозитория:
```bash
npm run back
```

Сервер поднимется на порту `3000` и будет слушать все сетевые интерфейсы (`0.0.0.0`). Папка для сохранения файлов (`uploads/`) находится в `backend/uploads/`.

## Переменные окружения

Создайте файл `.env` в папке `backend/`:

```env
DATABASE_URL="postgresql://localdrop_user:supersecretpassword@127.0.0.1:5433/localdrop_db?schema=public"
APP_PIN="ваш_pin_код"
ADMIN_PASSWORD="ваш_пароль_администратора"
JWT_SECRET="длинная_случайная_строка"
```

| Переменная | Описание |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL. При гибридном запуске используйте `127.0.0.1:5433` |
| `APP_PIN` | PIN-код для входа обычных пользователей (guest) |
| `ADMIN_PASSWORD` | Пароль для входа с правами администратора |
| `JWT_SECRET` | Секретный ключ для подписи JWT-токенов |

## Конфигурация безопасности

Все лимиты и пороги безопасности централизованно настроены в файле `src/rate-limits.config.ts`:

- **Глобальный лимит запросов:** 500 запросов в минуту
- **Лимит авторизации:** 5 попыток в минуту
- **Максимум неверных PIN:** 10 попыток (после — перманентный бан IP)
- **Порог DDOS-блокировки:** 10 ошибок throttling за минуту
- **Время жизни JWT-токена:** 30 дней
