# Local Drop

Веб-сервис для обмена файлами, заметками и буфером обмена в локальной сети. Кроссплатформенная альтернатива AirDrop, работающая прямо в браузере. Проект реализован в виде монорепозитория (NPM Workspaces).

## Основные возможности
- **Файловый менеджер:** Загрузка, скачивание и удаление файлов. Поддержка Drag-and-Drop.
- **Иерархия папок:** Создание папок, навигация (хлебные крошки), перемещение файлов и папок перетаскиванием.
- **Общий буфер обмена:** Мгновенная синхронизация текста и ссылок между устройствами.
- **Заметки:** Создание и редактирование заметок с тегами.
- **Real-time:** Мгновенное обновление UI на всех клиентах через WebSockets (Socket.io).
- **Просмотрщик:** Встроенный полноэкранный viewer для фото и видео.
- **Безопасность:** Авторизация по PIN-коду, защита от брутфорса, блокировка подозрительных IP.

## Стек технологий
- **Frontend:** Angular 18+ (Standalone, Signals, Material 3).
- **Backend:** NestJS, TypeScript, Socket.io.
- **База данных:** PostgreSQL 16, Prisma ORM.
- **Инфраструктура:** Docker, Docker Compose, Nginx.

## Быстрый старт

### Вариант 1. Гибридный запуск (Рекомендуется для разработки и домашнего использования)

База данных работает в Docker, а бэкенд и фронтенд запускаются напрямую на вашей машине. Это обеспечивает мгновенный hot-reload при разработке и корректное определение IP-адресов клиентов в локальной сети.

**Требования:** Node.js 18+, Docker, Docker Compose.

#### Запуск с нуля (после `git clone`):
```bash
npm run setup
```
Эта команда автоматически:
1. Установит все зависимости.
2. Соберёт общую библиотеку типов (`@local-drop/shared`).
3. Поднимет PostgreSQL в Docker.
4. Применит миграции базы данных.
5. Синхронизирует файлы из папки `backend/uploads` с базой данных.
6. Соберёт бэкенд и фронтенд в production-режиме.
7. Запустит приложение.

#### Запуск собранного проекта (production):
```bash
npm run all
```

#### Запуск в режиме разработки (hot-reload):
```bash
npm run dev
```
> Перед первым запуском `dev` убедитесь, что база данных поднята: `npm run db:up`

#### Доступ к приложению:
- С вашего компьютера: `http://localhost:4200`
- С других устройств в сети: `http://<ВАШ_IP>:4200`

---

### Вариант 2. Полный запуск через Docker

Все сервисы (база данных, бэкенд, фронтенд) запускаются в изолированных контейнерах. Подходит для серверного развёртывания.

```bash
npm run docker:up
```
Приложение будет доступно по адресу `http://<ВАШ_IP>:80`.

> **Примечание для Windows 10:** Docker Desktop на Windows использует NAT, из-за чего бэкенд внутри контейнера видит все клиентские подключения под одним IP (`172.x.x.1`). Для корректной работы системы безопасности (баны по IP) рекомендуется использовать гибридный запуск (Вариант 1).

## Команды

| Команда | Описание |
|---|---|
| `npm run setup` | Полная установка и запуск с нуля (после `git clone`) |
| `npm run all` | Сборка и запуск production-версии |
| `npm run dev` | Запуск бэкенда и фронтенда в режиме разработки (hot-reload) |
| `npm run back` | Запуск только бэкенда (порт 3000) |
| `npm run front` | Запуск только фронтенда (порт 4200) |
| `npm run build:all` | Сборка всех компонентов без запуска |
| `npm run build:shared` | Сборка общей библиотеки типов |
| `npm run build:back` | Сборка бэкенда |
| `npm run build:front` | Сборка фронтенда |
| `npm run db:up` | Запуск PostgreSQL в Docker (порт 5433) |
| `npm run db:down` | Остановка PostgreSQL |
| `npm run db:migrate` | Применение миграций Prisma |
| `npm run db:sync` | Синхронизация файлов из `backend/uploads` с базой данных |
| `npm run docker:up` | Запуск всех сервисов через Docker |
| `npm run docker:down` | Остановка всех Docker-контейнеров |

## Структура проекта

```
local-drop/
├── frontend/          # Angular SPA-клиент
├── backend/           # NestJS REST API + WebSocket сервер
│   ├── prisma/        # Схема БД и миграции
│   ├── src/           # Исходный код бэкенда
│   └── uploads/       # Хранилище загруженных файлов
├── shared/            # Общие типы (@local-drop/shared)
├── docker-compose.yml # Конфигурация Docker (только БД в гибридном режиме)
└── package.json       # Корневые скрипты монорепозитория
```

## Настройка сети (ZeroTier / Локальная сеть)

Для доступа к приложению с других устройств:

1. Убедитесь, что все устройства находятся в одной сети (Wi-Fi, Ethernet, ZeroTier и т.д.).
2. Узнайте IP-адрес вашего компьютера в этой сети.
3. Откройте порты **4200** (фронтенд) и **3000** (бэкенд) в брандмауэре.
4. На других устройствах откройте браузер и перейдите по адресу `http://<ВАШ_IP>:4200`.

> Фронтенд автоматически определяет адрес бэкенда через `window.location.hostname`, поэтому никаких дополнительных настроек не требуется.

## Переменные окружения

Создайте файл `backend/.env` на основе `backend/.env.example`:

```env
DATABASE_URL="postgresql://localdrop_user:supersecretpassword@127.0.0.1:5433/localdrop_db?schema=public"
APP_PIN="ваш_pin_код"
ADMIN_PASSWORD="ваш_пароль_администратора"
JWT_SECRET="длинная_случайная_строка"
```
